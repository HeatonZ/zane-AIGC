# 电商套图 V2 场景设计

状态：场景方案稿；未修改业务代码、服务端场景或发布版本，未调用生图服务。

## 设计目标

V2 重新设计的是“AI 如何理解商品、规划一整套图、生成并交付”的场景流程，不改工作台页面。目标是让一套图像有明确销售叙事、每张承担不同任务、整组视觉统一，同时尽量减少商品失真、虚构卖点和模型乱写字。

**场景定义**：把已确认的商品资料变成一套有统一视觉规则的完整电商成图；先审核商品事实和整套策划，再审主视觉样张，确认后逐张生成、复核并交付原图。

## V1 现状与 V2 方向

现有 AI 场景已经有数量校验、样张先审、确认后逐张生成和最终人工复核，这些有效闸口保留。当前模板主要依赖一段较长的自由文本提示词来约束整套风格和每张的差异；所有商品参考图与风格图又会一起传到每一张，视觉规则、商品事实、单张任务不够结构化。生成效果一差，很难判断是事实、构图、参考素材还是文案出了问题。

V2 把场景拆成三个可以分别审阅的创作对象：**商品事实卡、整套视觉圣经、逐张销售脚本**。先把商品讲对，再设计一套有变化但不散的图片，不直接从用户的一句话跳到多张生图。

## 场景输入设计

| 输入 | 必填 | 用途 |
|---|---:|---|
| 项目名称 | 是 | 运行和草稿标题 |
| 商品参考图 | 是 | 商品外观依据；建议正面、侧面、关键细节和包装各有清晰来源 |
| 参考图说明 | 否 | 按上传顺序说明 P1/P2/P3 对应的角度或细节，减少模型看错图 |
| 风格参考图 | 否 | 只提供色彩、材质、光线、设计气质，不提供商品事实 |
| 已确认商品资料 | 是 | 商品名、准确规格、卖点、包装内容、不能变化的外观；未知项明确留空 |
| 目标人群与使用情境 | 否 | 约束生活场景和视觉语气，不推导产品性能 |
| 本套图目标 | 是 | 例如新品首发、主打某个已确认卖点、强调细节或使用情境 |
| 创意方向补充 | 否 | 用户指定的色彩、参考感觉、禁用元素等 |
| 图片数量与画幅 | 是 | 默认 5 张；按现有基础步骤支持范围生成，不自动切换平台规则 |
| 图中文字策略 | 是 | `无字`、`仅使用用户给定原文`、`允许少量非事实型短句` 三选一；默认仅使用用户给定原文 |

不增加用户填写随机种子、节点参数等必填项。已有画幅和分辨率配置仍由场景输入契约约束；目标平台尺寸若要支持，作为显式配置，不让模型猜平台规范。

## 套图叙事设计

默认五张构成一条完整商品信息链，不把“六种固定卡片”机械套到每类商品：

1. **主视觉**：先认出是什么商品、视觉记忆点在哪里；商品主体清楚，作为整套的风格锚点。
2. **核心价值**：只表达一个有资料依据的购买理由；使用独立构图和信息层级，不重复主视觉。
3. **结构细节**：放大参考图能证实的结构、表面或使用方式；不推测隐藏结构和材质性能。
4. **使用情境**：让目标人群理解商品如何进入真实生活；人物、场景和道具不能暗示未经证实的功效。
5. **规格 / 包装 / 第二卖点**：资料和参考图充分时再用规格或包装；信息不足时改为另一项已证实价值或场景，不生成虚构参数、附件和认证。

数量不是模板复制次数。每张必须有独立的沟通任务，并在商品角度、景别、留白位置、背景层次或图文结构中至少体现一处明显变化；整套共用同一视觉圣经。若输入资料支撑不了所选张数的不同内容，计划审核应退回补充真实卖点或减少张数，不用换背景的重复图填满。

## 场景流程

```mermaid
flowchart LR
  A[商品图片与已确认资料] --> B[Writer 商品事实卡]
  B --> C[Writer 整套视觉圣经与逐张销售脚本]
  C --> D[data.zip 数量、顺序、结构校验]
  D --> E[人工审核事实卡、视觉圣经和整套计划]
  E --> F[AIXG 逐张完整成图提示词]
  F --> G[data.zip 对齐计划、参考与提示词]
  G --> H[ComfyUI 生成主视觉样张]
  H --> I{样张审核}
  I -->|退回| F
  I -->|确认| J[ComfyUI 逐张生成剩余图]
  J --> K[逐项成图审核与原图交付]
```

全部复用 Writer / AIXG、`data.zip`、基础媒体选择、ComfyUI、通用审核和 `for_each`。不加电商专用执行器、并行任务数据库或浏览器侧业务状态。

## Writer 输出契约草案

### 1. 商品事实卡 `product_truth`

- `confirmed_facts`: 用户提供且可逐条引用的 `{id, statement, source}` 列表，来源标明为商品资料或参考图序号。
- `visible_invariants`: 商品参考图能直接看到且成图必须保持的 `{id, statement, imageRef}` 列表，例如颜色、轮廓、Logo、部件关系、包装文字。
- `unknowns`: 缺失或图片无法确认的信息，以及生成更多规格/包装图前需要补充的问题。
- `do_not_claim`: 由缺失资料推导出的风险声明，例如未提供时不得声称防水、保温、食品级或某项认证。

只有 `confirmed_facts` 可支撑功能、规格或性能文案。场景创作可以使用人物、桌面、户外等视觉元素，但不能把它们当成性能证据。

### 2. 整套视觉圣经 `visual_bible`

输出结构化字段，而非一句风格形容词：

```json
{
  "concept": "一句可执行的创意概念",
  "palette": ["主色", "辅助色", "点缀色"],
  "lighting": "光线方向、软硬与色温",
  "surfaceAndBackground": "背景与材质语言",
  "graphicLanguage": "图形、线条、纹理或标注的用法",
  "typeHierarchy": "标题、辅助信息与品牌标识的视觉层级",
  "productRules": ["商品保持规则"],
  "variationAxes": ["跨图变化维度"],
  "avoid": ["整套共同禁用内容"]
}
```

字体和版式由图像模型在完整成图中表现；不输出坐标、程序排版数据或等待后置填字的无字底图。

### 3. 逐张销售脚本 `cards`

每张只保留能推动成图的必要信息：

```json
{
  "ordinal": 1,
  "id": "稳定且唯一的图片ID",
  "role": "hero | selling_point | detail | lifestyle | specs | package",
  "conversionTask": "这张图要帮助用户理解或决定什么",
  "factRefs": ["来自商品事实卡的已确认事实"],
  "copy": ["按文字策略允许出现的短文案"],
  "composition": "与其他卡不同的主体构图、景别、视线和留白",
  "scene": "具体背景、光线和道具",
  "productTreatment": "主体角度、比例和必须保持的外观",
  "brief": "可直接生成完整电商成图的自然语言设计"
}
```

机器校验要求：张数与请求一致；`ordinal` 必须从 1 连续递增；`id` 唯一；`role` 在受支持枚举内；每张都有任务和完整 brief；`factRefs` 引用事实卡中的 ID；`copy` 遵守所选文字策略。通用 schema 可以校验类型、长度、数量、ID 和顺序，但不能独立证明一句话是真的；事实引用和文案准确性必须在方案审核中逐条核对。无商品规格或包装依据时，`specs` / `package` 自动让位，不用空白模板或虚构内容补齐。

## 套图方案示例

示例输入只确认：**山岚随行杯、480 ml、杯盖可拆洗**；参考图可见深绿色杯身和黑色杯盖；用户给定短句“刚好装下，刚好带走”。没有提供保温时长、材质等级或包装附件，因此这些信息不进入成图。

整套视觉圣经：自然窗光、岩灰和松针绿、柔雾背景、局部暖色反光；标题简短且不遮挡商品；图形只用细线、圆点和少量尺度标记。五张共用这套视觉规则，但不复制主图机位。

| 顺序 | 卡片角色 | 这张要完成的事 | 构图与画面变化 |
|---:|---|---|---|
| 1 | 主视觉 | 让人一眼识别商品与本次主题 | 杯身三分之四角度，占画面主位；深绿渐变和窄侧光，放入用户给定短句 |
| 2 | 核心价值 | 讲清 480 ml 的容量信息 | 俯拍开盖与杯体分层，容量数字成为视觉焦点；不加未确认的性能文案 |
| 3 | 细节特写 | 呈现可拆洗杯盖 | 杯盖与杯口近景，结构按参考图展示；画面不扩展隐藏部件 |
| 4 | 使用情境 | 表达通勤携带的生活方式 | 低机位桌边/手持环境，商品保持清晰；人物和环境不暗示保温、防漏等性能 |
| 5 | 另一项有依据的信息 | 避免重复主图，同时不编造卖点 | 若补充了包装实物则做包装清单；否则改做不同视角的造型呈现，不伪造配件或规格 |

这只是场景策划示例，不是固定模板；商品事实不足时第五张计划应明确建议补资料或减少张数。

## 逐张提示词规则

AIXG 每次只处理一张计划，输入包括该卡、共享视觉圣经、商品事实卡、参考图编号映射和本张真实附件。输出一条完整自然语言成图 prompt：

- 开头明确只生成这一张最终电商图，包含背景、图形、构图与文字设计。
- 锁定本张的 `conversionTask`、`composition`、`productTreatment`，并执行共享视觉圣经。
- 商品参考图只作商品身份和可见结构依据；风格图只作美术依据。使用基础媒体返回的实际编号，不猜测或重排编号。
- 只写入 `copy` 中允许的短句。没有授权文字时明确不生成可读文字；不让模型临时发明参数、促销、品牌、认证或功效。
- 保留商品身份，但不承诺图生图能做到像素级复刻。若精确 Logo、标签或商品结构必须逐像素准确，应先使用原图保真方案，不把 AI 重绘描述成保证精确。
- 保持不同图片的构图差异；不能把上一张的镜头和布局复制到整套。

所有输出仍是模型直接生成的完整原图。中文字和商品细节有生成误差的可能，样张及整套结果都要人工审阅。

## 审核闸口

### 方案审核

- 信息链是否完整：主视觉、价值、细节、情境、可信信息各有合理位置。
- 每张是否有不同销售任务、主体角度和构图。
- 所有功能性表述能否追溯到用户给出的事实。
- 风格圣经是否可执行且适合商品，逐张 brief 是否真正使用它。
- 文案数量和长度是否受控；规格、包装不足时是否已换成有依据的画面。

### 样张审核

- 商品轮廓、颜色、Logo、部件和包装是否仍对应参考图。
- 画面是否真正完成主视觉设计，而非普通商品照片或空背景。
- 图中文字是否符合文字策略且可读；构图、光线、材质是否建立了后续套图方向。
- 不通过时反馈具体的事实、商品外观、构图、风格或文案问题，先重做样张，不生成剩余图片。

### 成图审核

- 逐张确认商品事实、图片顺序、图中文字、构图差异与整组视觉一致性。
- 每个逐项任务严格一张图；失败项保留原 ID 和位置，按现有恢复机制处理，不跳过后错配。
- 最终收集模型原始图片及复核信息；不自动贴字、裁切、排版或合成。
