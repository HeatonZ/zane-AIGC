# 电商套图场景

## 定位与兼容范围

新增独立场景 `commerce_pack`，不替换原有 `commerce` 场景，不增加专用工作台页面。复用现有创作表单、流程配置、发布版本、逐项执行、取消、续跑和运行记录。

流程：商品资料 → 选择生成方式 →（AI模式）商品事实与逐张脚本 → 逐张底图 → 多平台排版 → 成图和清单 → 按平台 ZIP 下载。

## 安装

全新工作区的默认场景已包含电商套图。已有共享工作区不会自动追加默认项，使用现有工作台的“导入场景”导入 `examples/scenes/commerce-pack.json`，检查后发布；或在当前仓库中运行：

```powershell
npm run build
# 重启正式服务，保持原 .env.production 与 APP_DATA_DIR
npm run start
```

另开终端，在已初始化的共享工作区中安装并发布：

```powershell
npm run scene:install:commerce
# 也可指定服务地址：
npm run scene:install:commerce -- http://127.0.0.1:8798
```

安装脚本只追加新场景、对应流程和发布版本；不会改旧场景、草稿、连接设置或选项预设。若已有相同场景ID则不覆盖。安装前的工作区备份写入 `backups/commerce-pack/`。AI步骤优先使用已启用的 `writer` Profile，否则选第一个已启用 Profile；可在流程配置中修改。手动导入会生成新的场景ID，适配器仍正常工作。

## 使用

1. 工作台打开 **电商套图**。
2. 输入项目名、商品名和有事实依据的卖点，上传至少一张参考图。
3. 选择生成方式、目标平台和视觉风格；按需补充真实规格、包装清单、外观约束。
4. 运行流程。默认六种卡片 × 国内三平台，共18张JPEG。
5. 检查缩略图与技术清单；运行结束后点击 **按平台打包下载**。失败/取消记录可下载已完成卡片。

### 两种生成方式

- **AI场景重绘**：Hermes输出商品事实和摄影脚本，ComfyUI图生图。普通平台共享每种卡片的一张AI底图；需要白底主图的平台单独生成白底版本。不要把“一致性提示”当作像素级商品锁定，需核对结构、颜色、Logo和包装文字。
- **原图保真排版**：跳过Hermes和Comfy生成，直接将参考图按比例缩放、保留完整画面后排版。不自动抠图，不生成新角度/场景。保留图片内容，但缩放、EXIF旋转和JPEG编码会改变像素。适合有完整实拍素材、不能接受商品外观变化的场景。

后置文字只来自用户填写的商品名、卖点、规格和包装清单，固定卡片标签不包含新增产品事实；不使用AI编造的宣传文案。文案过长会报错，而不是静默截断；可缩短或加大画布。

### 卡片与参考图映射

`shot_types` 默认：

```json
["hero", "selling_point", "detail", "lifestyle", "specs", "package"]
```

| ID | 卡片 | 原图模式默认参考图索引 |
| --- | --- | --- |
| hero | 主视觉 | 0 |
| selling_point | 卖点展示 | 1 |
| detail | 商品细节 | 2 |
| lifestyle | 使用场景 | 3 |
| specs | 规格参数 | 4 |
| package | 包装清单 | 5 |

索引超出实际参考图数量时使用最后一张；只有一张参考图时六种卡片都会使用该图。可删掉不需要的类型，或通过对象指定参考图（从0开始）：

```json
[{"id":"hero","reference_index":0},{"id":"detail","reference_index":2}]
```

`reference_index` 用于原图排版；AI模式按工作流绑定传入参考图列表。每种卡片只能出现一次，最多六种。Hermes脚本需为所选ID恰好返回一项，不接受重复或漏图。

## 平台适配

以下均为**设计/导出预设**，不是所有刊登位置、类目都适用的官方规范，也不保证平台审核通过：

| 平台ID | 名称 | 默认画布 | 安全留白 |
| --- | --- | --- | --- |
| taobao | 淘宝 / 天猫 | 1600 × 1600 | 80 |
| jd | 京东 | 1600 × 1600 | 80 |
| pdd | 拼多多 | 1200 × 1200 | 60 |
| douyin | 抖音电商 | 1200 × 1200 | 72 |
| xiaohongshu | 小红书 | 1242 × 1656 | 80 |
| amazon | Amazon | 2000 × 2000 | 100 |

目标平台组合包含单平台、国内三平台、国内五平台、全部六平台和自定义平台。`platform_profiles` 可覆盖尺寸、留白和文字开关：

```json
[{"id":"taobao","width":1600,"height":1600,"safeMargin":80,"showText":true}]
```

新增平台需选择“自定义平台”，填写：

```json
[{"id":"custom_store","name":"自有商城","width":1200,"height":1600,"safeMargin":60,"showText":true,"whiteHero":false}]
```

宽高分别为600–4000整数；最多12个平台；留白范围为0到短边四分之一。ID唯一，只允许小写字母开头的字母/数字/横线/下划线。

Amazon的`hero`始终禁用后置文字，并使用纯白画布；这项保护不能通过配置取消。原图背景、阴影、主体占比与实际平台/类目规则仍需人工复核。其他平台设置`whiteHero:true`也可启用白底主图模式。

## 模型工作流与字体

AI模式默认使用现有 `Zane/i2i_UI.json`：图像/提示词/负面提示词绑定到471，随机种子绑定到476，图片输出绑定到461。可在“流程配置”中修改Comfy工作流和绑定，电商适配器所需的命名输入与`commerce_manifest`输出会保留。底图工作流每次必须只输出一张图片。

原图模式不需要可用的Hermes/Comfy生成服务。排版使用Sharp和系统字体；中文默认采用Microsoft YaHei，可选设置`ZANE_COMMERCE_FONT_FILE`指向本机中文字体文件。不存在的字体路径会明确报错。

## 结果、质检与续跑

成图写入当前项目 `.zane/runs/<运行ID>/outputs/media/commerce-<平台>-<卡片>.jpg`。输出包含可预览的`images`与`commerce_manifest`，清单记录来源运行、参考图索引、尺寸、文件大小、SHA256、文字来源、生成方式与人工复核项。

技术校验覆盖尺寸、JPEG格式、完整排版区域与文件有效性；不等同于语义商品识别、功效核查、Logo校验或平台合规审核。

卡片按现有`for_each`执行，默认并发2、失败继续。失败/取消后使用现有“从失败处继续”仅重做失败项；新运行保留成功项的原归档来源。每项要完成所有目标平台才标记成功，失败项内尚未确认的文件不会作为成功结果导出。

ZIP接口：`GET /api/v1/runs/<运行ID>/commerce-pack.zip`。ZIP按平台目录保存，另含`manifest.json`和`REVIEW.txt`；失败/取消包标记`incomplete:true`。活动运行禁止导出，路径/来源/重复名均校验。续跑下载允许沿合法祖先链引用旧图。下载中断不取消生成任务。
