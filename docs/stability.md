# 稳定性加固：执行、输入快照与媒体归档

本轮只加固现有创作链路，不新增创作功能，不引入外部服务，不改变 SQLite schemaVersion。

## 1. 提交与进度同步

- 创作页立即显示“正在准备素材并确认任务提交”，但运行详情订阅在服务端确认接受后才启动，避免提前读取尚未提交的 ID。
- GET /api/v1/runs/:runId 在任务仍准备素材时返回 409 / RUN_PREPARING，并提供 Retry-After: 1；确实不存在的任务仍返回 404。
- POST 响应丢失或返回 5xx 时，若客户端已经指定运行 ID，只查询这个 ID，不自动重新 POST，也不重新分配 ID。查到运行后继续等待原任务。
- 仍未查到的未知提交最多重试 60 次，之后明确提示“提交结果暂时无法确认”，附原运行 ID，提醒先查看记录、不要重复提交。它不等同于后台任务失败。
- 已读到运行后，临时网络中断不会在 60 次失败后被误判为永久失败；继续退避重连直到读到终态、遇到明确的永久错误或用户离开页面。
- 每次详情读取设 15 秒超时。SSE 手动重连携带已收到的事件游标；旧连接消息和倒序消息不会覆盖当前状态。
- 停止等待会关闭订阅、清理计时器与读取请求，不取消已经接受的后台任务。取消任务仍使用显式 cancel API。

## 2. 状态转换

- 已提交的取消意图优先于执行器在收尾阶段迟到的 completed / waiting 结果。
- 执行结束后或旧执行产生的迟到 checkpoint 不能把任务重新写成 running，也不能污染同一运行后续的确认执行。
- 保留已完成的步骤结果以供显式续跑；服务关闭和用户取消仍分别记录为 stale / cancelled。

## 3. 本地输入快照

- 排队前检查本地媒体是否存在且为文件；不可读输入返回 400 / INPUT_MEDIA_UNAVAILABLE，避免前序模型已经执行后才发现参考素材缺失。
- 执行器与持久化提交快照实际读取 inputs/files 下的副本，不再只保存副本却继续使用原文件。删除或改写原素材不改变已接受任务的本地输入。
- 文件名加入字段标识，避免两个字段清洗后重名而覆盖素材；来源 originalPath 仍保存在输入清单中。
- 准备目录使用独占创建。复制、归档或数据库提交失败时，只回滚本次新建且未提交的目录；不覆盖、不清理已有运行。清理失败另记警告，不掩盖原始失败原因。
- 重启先根据输入清单恢复旧版 queued 快照中的本地引用，并提交恢复后的队列快照。某一任务的归档损坏或本地输入丢失会单独标记 stale，不阻止服务启动或其他正常任务恢复。

上述固定副本保证针对本地输入文件。直接引用外部 URL 或未归档上游附件，仍依赖外部服务可用；本轮没有把全部远程输入改成离线素材。

## 4. 输出归档

- ComfyUI 输出改为流式落盘，不再通过 arrayBuffer 同时缓冲完整视频。
- 同一运行最多两个媒体下载同时进行；同一媒体的并发归档合并为一次下载。
- 先写独立临时文件，完整下载后才发布最终文件。中断或失败不留可预览的半文件、不污染成功缓存，也不截断已有完整文件。
- 取消会中断活动 HTTP 流并移除等待下载；文件系统拒绝写入时释放未消费的上游。
- 已归档的祖先运行媒体保持原引用，不再按上游原文件名重新下载，避免上游同名文件后来变化时替换历史结果。
- 单文件限制 2 GB，单次下载超时 120 秒。空文件、超限、不完整下载和文件系统故障返回原结果并记录归档警告，后续归档可重试。

归档警告意味着该输出可能仍依赖原上游，不能把它当作已经完成独立媒体备份。素材库上传仍沿用现有单文件 250 MB raw body 接口，本轮未改变上传协议。

## 验证与启用

回归覆盖提交响应丢失、长断网、SSE 游标重放、读取超时、取消收尾竞态、迟到进度、本地素材删除、旧队列恢复、单任务归档损坏、数据库提交失败、并发归档、文件系统故障，以及真实本地 HTTP 流取消。

执行 npm run check 和 npm run test:long-video:smoke；全部使用隔离数据及本地/模拟上游，不调用真实付费模型。

构建不会替换已运行进程中加载的服务端代码。正式后台需要在合适时机重启后才能启用服务端修复；不要在有生成任务时直接运行带停服前置步骤的 start:prod。已开始但在重启时被中断的外部生成仍需要人工决定是否续跑，本轮不承诺跨外部服务 exactly-once。
