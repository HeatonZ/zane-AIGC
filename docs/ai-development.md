# AI 配套是功能完成条件

适用：新增场景功能、能力包、执行/反馈/审核、素材、选版、业务配置及相关修改。仓库根 `AGENTS.md` 已将本约定纳入后续开发指令。

## 基础优先，专用由自定义代码替代

新增场景先尝试基础步骤组合；Profile、提示词、字段、节点绑定及通用逐项/条件/审核配置能够表达的差异，不新增场景专用执行器。场景特有的数据传递、模板拼装、素材映射与结构化控制用 core.code 自定义代码在隔离沙箱内表达；基础能力不足时先补强或拆出可复用能力，不按场景名称专用化。能力目录统一，不再分基础/专用等级：步骤只声明 `usage.whenToUse`，退役的执行方式（含旧 H3 适配与电商图包整包）标记 `usage.compatibilityOnly`，仍注册可执行以兼容已有发布快照与历史运行，不作为新步骤推荐。未声明 usage 的旧扩展补默认说明，不自动改动原流程。

UI、HTTP、MCP 读取同一能力目录；`list_capabilities` 只有一个扁平目录，不再接受 `tier` 参数，目录按安装注册顺序返回。目录分页与 revision 必须一致，发布/运行快照不得因展示分组改变。

## 场景只维护服务端一套

场景目录、流程、发布版本、选项预设和任务草稿的权威持久化仅在服务端 SQLite。浏览器启动只读服务端：不存在、空目录、连接失败或快照不兼容都不能回退到 localStorage / 内置场景。未初始化时由用户显式建立空工作区，或通过既有 AI 服务明确创建场景；不要把旧浏览器场景自动导入。

浏览器可以保留尚未确认写入的 outbox 以防丢失，但它不是另一份场景库。重载展示服务端快照，旧 outbox 不自动应用或重放；明确恢复必须先读取服务端对账，沿用原 ID / base，仍由服务端执行冲突校验。无效 outbox 保持原样，不静默过滤；明确放弃时先读成功、检查无新编辑及在途保存，再清除。纯模板 / 导入转换不应包含浏览器持久化，且不能自动发布。

## 身份与归属也是完成条件

不引入用户工作区，一个系统维护一套配置。所有业务入口先验证服务端身份；管理员专用能力不能只在导航隐藏。普通用户可使用的场景取实时授权与固定发布快照，本人草稿/运行/素材从验证身份写入 ownerUserId 或 userId，不接受客户端伪造归属。历史未归属数据保持管理员专用。

新增操作要登记 admin/authenticated 边界，按权限过滤后分页。任务输出/媒体/HEAD/Range、等待/流式响应和旧兼容 API 同样校验；异步操作在落库/入队前再次验证当前账户、会话/凭证与授权。撤销授权不自动取消既有运行，继续执行的操作重查授权与状态。管理员与用户各用本人 API token，通过同一 HTTP/MCP 服务；不得由 profile 名称或传入 userId 提权。

浏览器防丢 outbox 必须按身份隔离，保存/发布等待服务端回执。响应解码失败也算回执未知；保留原 ID 先对账，不自动换 ID 或重投。新功能回归应覆盖两用户隔离、无授权/已授权未发布、禁用/角色/密码/凭证变更、旧 revision 与跨身份游标。

## 每次开发的最小闭环

| 层 | 必须交付 |
| --- | --- |
| 业务服务 | 一套权威实现和校验；UI/API/MCP 复用，不另建 AI 数据源 |
| 操作 | AI 可以发现并完成新业务；新增原子工具或扩展现有工具，不只做按钮 |
| 请求契约 | 参数类型、必填/默认值、枚举、素材/版本引用、完整替换还是部分更新 |
| 返回契约 | 稳定对象 ID、revision、状态、必要输出、游标/分段信息、下一步 |
| 副作用 | read/write/execute、是否发布/生成、能否取消、是否可能计费 |
| 恢复 | 可区分的错误码、冲突对象/当前 revision、响应丢失的对账路径；不盲目重投 |
| 上下文 | 不搬无关场景/完整历史；大值明确省略或分页，不能把摘要当完整快照 |
| 文档与发现 | 功能矩阵、在线手册、OpenAPI、MCP schema 同步；参数和默认值来自同一权威来源 |
| 验收 | API/服务回归 + 真实 stdio 隔离闭环；不使用生产数据或真实生成服务 |

## 必改入口

- 操作与请求：`server/ai/operations.ts`、`server/ai/schemas.ts`、`server/ai/sceneSchemas.ts`。
- 响应与 OpenAPI：`server/ai/openapi.ts`。不要只描述请求而把关键返回含义留给 AI 猜。
- 业务覆盖矩阵：`server/ai/features.ts`。同一业务扩展若复用已有工具，也要更新覆盖说明。
- 操作流程和恢复：`server/ai/guide.ts`；通过生成器更新 `docs/ai-operator.md`、`docs/ai-tools.md`、`docs/ai-openapi.json`、`docs/ai-foundation.md`。
- 参数变更须同时验证 HTTP 与 MCP；不能只让前端 API 客户端支持。
- Hermes 技能只提供通用角色/操作策略，参数以实时 schema 为准；不要把新增业务写死为 profile 的唯一职责。

## 需要覆盖的边界

- 无效/缺失输入、未知键、错误类型、无效枚举、缺少或不兼容能力。
- 固定发布版本和素材版本不随草稿/共享选项改变。
- 同对象并发冲突；无关对象编辑不应误冲突或被覆盖。
- 提交/发布响应丢失；新 ID 在调用前保存，不能自动生成第二次副作用。
- 摘要/详情/分页/大值省略的区别明确；旧或跨对象游标被拒绝。
- 审核、取消、恢复、局部重做等保持原状态机。
- 现有 UI 与历史运行、场景元数据和扩展字段兼容。

## 本机接入与只读核验

本机用户环境变量已提供 `ZANE_ADMIN_TOKEN`（≥32 字符运维管理凭证，服务端识别为 `@operator`/admin）：HTTP API 作 `Authorization: Bearer`，MCP 入口作 `ZANE_API_TOKEN`，两条入口都可用。判断“能不能访问工作台”之前先实测，不要凭印象宣称没有凭证。

```powershell
Invoke-RestMethod http://127.0.0.1:8799/api/health                       # 无需鉴权，确认服务在跑
$h = @{ Authorization = "Bearer $env:ZANE_ADMIN_TOKEN" }
Invoke-RestMethod http://127.0.0.1:8799/api/v1/self/account -Headers $h  # 应返回 @operator / 运维管理员 / admin
$env:ZANE_API_TOKEN = $env:ZANE_ADMIN_TOKEN                              # 启动 MCP 前显式传入同一凭证
```

全局 Codex 配置已注册 `zane-workbench` 条目（2026-10-10 按 `examples/mcp/codex.toml`，令牌取本机 `ZANE_ADMIN_TOKEN` 注入 env 表，改动前备份 `config.toml.bak-20261010`）；注册或修改配置后需重新加载 MCP 连接才生效，未生效时用上面的命令直连。

MCP 入口与 `npm run ai:doctor` 只读取启动环境，不自动加载项目 `.env*`；终端命令不会自动继承 Codex 只传给 MCP 子进程的环境。检查配置只输出存在性、长度/前缀、是否启用、地址与错误类别，401 是鉴权未通过、403 是权限不足。密钥只存在于本机环境变量或本机 Codex 配置，不进仓库、日志、回复、AGENTS.md 和示例文件；不因此重启工作台、Hermes Gateway 或 ComfyUI。

## 命令和自动门禁

```powershell
npm run docs:ai
npm run check
```

`npm test` 自动发现新测试。AI 契约回归检查每个工具在功能矩阵中有归属、矩阵工具真实存在、OpenAPI 与 MCP 请求一致、JSON 引用可解析；生成文档漂移会使检查失败。隔离 stdio 冒烟验证编译产物，新增基础闭环已覆盖场景创建→编辑→校验→发布→预检→本地执行→按需读结果。

自动门禁不能从 UI 代码推断每个功能的业务含义，不能替代开发者登记与评审；PR 检查表要求显式说明 AI 入口及测试。机器/凭据安装等运维步骤若不适合业务工具，要写清使用专用配置入口的原因，不能借此漏掉业务操作。

## 发布前

全量检查通过后，在空闲的正式工作台正常切换，并执行 Node/Hermes 只读 doctor；保留数据与服务基线。不要把隔离本地执行通过宣称为真实付费生成质量已验收。
