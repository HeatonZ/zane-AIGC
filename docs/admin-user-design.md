# 管理端与用户端设计

设计日期：2026-10-04。

状态：第一版已在代码中实现管理员/用户双入口、账户与直接场景授权、本人草稿/任务/媒体、HTTP/MCP 同权。本文记录实现范围；机器契约以生成的 AI 文档为准。此次未切换正式工作台、未初始化正式账户、未改动 Hermes Gateway 或 ComfyUI。

## 1. 产品目标与范围

- 产品不再展示“工作区”“个人空间”“工作区切换”；一个系统维护一份场景配置。
- 现有页面定位为管理员后台，保留场景、流程、发布、预设、连接、任务和素材等管理能力。
- 增加用户管理。管理员创建、启停用户，配置各用户可使用的场景。
- 用户端只展示已授权且已发布的场景，负责填入业务输入、提交任务、处理当前任务要求的业务确认、查看自己的结果。
- 用户不配置流程、不修改提示词模板和模型连接、不管理发布、不读取他人的任务或素材。
- 第一版使用两种角色 `admin` / `user` 和直接场景授权；不引入组织、租户、工作区、可自定义角色矩阵或独立用户执行器。
- 场景继续使用基础能力和配置表达差异，授权不会复制场景、流程或发布版本。

## 2. 页面与入口

### 管理端 `/admin`

保留并调整现有导航：

- 概览：系统状态、待处理任务与管理操作。
- 场景管理：场景信息、流程配置、预设、校验、发布版本、管理员试用。
- 用户管理：用户列表、创建用户、账户状态、场景授权、密码重置与 AI 凭证管理。
- 任务管理：所有任务及其归属用户；历史未归属数据明确标识。
- 素材管理：管理素材及明确的共享范围。
- 系统设置：现有集成连接与运行设置。

现有创作页可保留为管理员试用入口，不把管理员编辑表单直接暴露给普通用户。

### 用户端 `/app`

- 可用场景：只显示当前账户获授权且已经发布的场景。
- 场景使用：业务说明、发布版输入表单、版本标识、提交与结果。
- 我的草稿：仅本人输入草稿，不包含流程编辑。
- 我的任务：仅本人任务、状态、结果和允许的任务操作。
- 我的素材：仅在素材归属与媒体访问隔离完成后开放，不能直接复用全局素材列表。
- 账户：当前身份、退出、本人 AI 凭证。

登录与首次管理员初始化独立于这两个入口。访问入口不能决定权限；管理员身份与用户身份必须来自服务端验证后的会话或凭证。

## 3. 用户与授权模型

### 用户

用户具有稳定 `userId`、唯一登录名、显示名、角色、启用状态、`revision`、创建时间和更新时间。密码摘要与会话信息不进入列表、AI 普通读取响应或日志。

- 首次初始化显式创建首个管理员；不提供默认密码，也不把匿名浏览器当作管理员。
- 普通用户初始授权为空；默认看不到任何场景。
- 账户禁用后不能继续发起操作，既有会话与 AI 凭证必须失效。
- 防止误禁用或降级最后一个有效管理员。
- 第一版优先停用而非硬删除用户，避免破坏历史任务归属。

### 场景授权

使用 `userId + sceneId` 关联，第一版仅表达“可使用”，不授予编辑、发布或修改执行流程的能力。

- 新建或导入场景不自动授权给所有用户。
- 在“用户管理”的用户详情中勾选场景，通过同一权威授权服务保存。第一版未提供场景详情的反向授权用户视图。
- 授权修改使用用户/授权集的 `revision` 冲突保护，不能以旧页面覆盖新授权。
- 用户可用目录 = 存在的场景 ∩ 当前授权场景 ∩ 已发布场景。
- 未发布场景可以预先授权，但在用户端不可用；管理端明确显示“授权已设置，待发布”。
- 用户页面标题、说明、输入契约取发布快照，不取管理员正在编辑的草稿。

## 4. 使用与发布规则

1. 用户读取当前授权目录，选择一个已发布场景。
2. 服务端返回业务展示信息、固定 `versionId`、输入契约和必要的选项，不返回完整工作流、内部提示词、连接密钥、本机路径或全局配置快照。
3. 用户打开表单后绑定该版本；管理员后续发布不会悄悄切换已打开表单。
4. 用户暂存输入走服务端本人草稿服务；输入框失焦后自动保存，切换页面、提交任务或离开表单时先冲刷待保存内容。保存成功以服务端回执和 `revision` 为准；响应丢失或 revision 冲突仍按原草稿 ID 对账。
5. 提交时保存稳定 `runId`，服务端重新检查账户状态、当前场景授权、发布版本与输入。
6. 服务端从自己的发布快照构造执行请求，复用现有校验、准备和运行服务。用户不能通过提交自定义 `workflow`、`userId`、项目目录或执行参数获得额外能力。
7. 新任务只能使用当前发布版本；如果打开表单后发布已改变，返回显式版本冲突，由用户确认新输入契约后重新提交，不自动换版。已经提交的任务保留原快照。
8. 撤销授权后禁止新任务和新的业务执行操作；已经接受的任务默认不自动取消，管理员可以单独处理。
9. 用户仍可查看本人既有任务与结果；涉及继续生成的审核、续跑、重做等操作再次检查当前授权和真实状态，不绕过审核。
10. 响应丢失查询同一对象/运行 ID，对账后决策，不自动换 ID 或盲目重发。

## 5. 数据归属与权限边界

登录与场景过滤不能单独构成完整用户系统，以下资源必须同时完成：

| 对象 | 普通用户边界 | 管理员边界 |
| --- | --- | --- |
| 场景目录和详情 | 授权的已发布业务视图 | 所有草稿与发布管理 |
| 输入草稿 | 仅本人，保存在现有 SQLite 的 user-drafts 集合 | 保留原有全局管理草稿；第一版不提供代用户编辑其输入草稿 |
| 运行记录、步骤结果 | 仅本人，使用业务响应；轮询/最长30秒有限等待，不开放管理 SSE | 全部管理响应与 SSE |
| 运行输出与媒体下载 | 校验任务归属后访问 | 管理访问 |
| 取消、审核、续跑 | 本人任务 + 状态允许；审核/续跑再检查当前授权，取消不要求保留场景授权；不允许修改流程/输出 | 原有管理能力与状态机 |
| 素材及素材版本媒体 | 本人上传和固定版本引用；第一版不开放共享、全局素材目录或任意服务器路径 | 管理访问 |
| 流程、预设定义、发布、连接、系统配置 | 无权访问 | 管理操作 |
| 用户管理和授权 | 无权访问；只能读取本人账户 | 管理操作 |

所有 HTTP 入口，包括旧 API、SSE、HEAD/Range、媒体和下载接口，都必须检查同一身份与对象权限。不能只隐藏导航，不能用“知道 ID/文件路径就能访问”的旧通道绕过。分页应先按权限过滤再分页，避免页数、总数和目录信息泄漏。

用户业务确认只开放必要的审核输入，不能直接给用户复用含完整流程和内部参数的管理端运行响应。

## 6. 服务端与 SQLite

继续使用现有权威服务、SQLite、运行状态机与执行器；不新增用户专属业务数据库，不建立 AI 旁路任务库。

- 增加账户、场景授权、会话/凭证元数据，放入现有 SQLite。
- 运行、输入草稿、素材等增加归属信息。归属从已验证身份取得，普通用户请求不能指定或替换归属。
- `WorkspaceService` 和当前 `workspace` 表可以暂时保留为内部全局配置实现；它不是产品上的工作区，也不是每个用户一份。不要仅为改名重写已经稳定的合并、发布与冲突机制。
- 管理端的旧配置 API 设为管理员专用。用户端没有读取完整工作区快照的能力。
- 原有 JSON 保持导出镜像性质，不成为授权或用户数据的第二个写入源。
- 浏览器只保留页面输入和必要的未确认防丢意图；防丢队列必须按身份与对象区分，退出/切换账户不能恢复上一个账户的编辑。
- 保存界面统一使用“未提交 / 保存中 / 服务端已保存 / 保存失败 / 版本冲突”等真实状态，不能以输入校验成功冒充保存成功。

实现使用 `AccessService` 统一账户、身份、会话/凭证与场景授权；`UserPortalService` 只组织用户业务视图和归属边界，场景准备、运行、素材仍委托既有 `AiSceneService`、`RunService`、`AssetService`，没有新增执行器或任务数据库。

## 7. HTTP / MCP / AI 配套

以下操作面已登记在契约1.4.0。完整参数、返回、默认值和副作用由 `server/ai/operations.ts` / `accessSchemas.ts` / `accessContracts.ts` 生成，不以本文代替机器契约：

### 管理操作

- `list_users`：分页，返回稳定 ID、状态、角色、revision；不含凭证摘要。
- `get_user`：单用户和授权摘要。
- `create_user`：调用前保留 userId；重复 ID/登录名有明确错误，响应丢失按同一 ID 对账。
- `update_user`：名称、角色、启停；必须带 revision。
- `reset_user_password`：明确副作用，旧会话/凭证处理规则；敏感参数不得写入日志。
- `get_user` / `set_user_scene_access`：读取用户时包含当前 sceneIds 和 revision；保存完整授权集，409 后重读，不覆盖。不重复新增同义读取工具。

### 当前身份的用户操作

- `get_current_user`：读取身份与能力；无副作用。
- `list_available_scenes` / `get_available_scene`：分页和固定发布业务契约，不返回管理草稿。
- 本人草稿的列表、读取、保存、更新；使用对象 revision。
- `prepare_own_scene` / `submit_own_scene`、本人运行查询/有限等待、输出/步骤/逐项分页与授权媒体访问；`cancel_own_run` / `review_own_run` / `resume_own_run`。用户审核只支持 approve/redo 和可选反馈，续跑只用原快照，不提供自定义流程/局部改输出的管理重做。
- 本人 AI 凭证创建、列表和吊销；凭证明文仅创建时返回，后续不提供回读。配置 AI 凭证不等于授权新场景，也不等于执行任务。

管理员 AI 与用户 AI 使用同一套 HTTP/MCP 服务，通过凭证角色与归属控制能力。Hermes 的 `comfyui-dev` 可以配置管理身份；普通用户 AI 使用本人凭证，不能靠 profile 名、工具参数或客户端声明提权。

本次同步交付：

- `server/ai/operations.ts`、参数 schema 和响应契约：类型、默认、必填、版本、错误、副作用与 nextAction。
- `server/ai/features.ts`、`server/ai/guide.ts`：功能发现、身份边界、授权与版本冲突处理。
- stdio HTTP 客户端的凭证传递与错误解释；禁止把管理员凭证放入浏览器端。
- `npm run docs:ai` 生成文档与漂移检查。
- HTTP、UI 和 MCP 同一权限与服务；管理工具对用户不可操作，用户端发现结果不能误导 AI 使用管理能力。

建议错误分类：`AUTH_REQUIRED`、`ACCOUNT_DISABLED`、`ADMIN_REQUIRED`、`SCENE_ACCESS_DENIED`、`SCENE_NOT_PUBLISHED`、`SCENE_VERSION_CHANGED`、`USER_REVISION_CONFLICT`。对其他用户的任务、素材等对象宜返回不泄露对象存在性的错误。

## 8. 现有系统迁移

- 现有场景、流程、发布、配置、任务及媒体原地保留，不为每个用户复制。
- 旧任务、旧草稿、旧素材没有可靠用户归属，默认仅管理员可见；不得自动发给首个普通用户或所有普通用户。
- 第一版不自动认领历史资源，也未提供历史归属迁移工具。如以后开放，必须提供显式归属操作与 revision 校验，先确认目标用户。
- 现有 UI 迁移为管理端；根入口按登录身份导航，而不是继续展示“工作区初始化”。
- 内部兼容 API 可以暂时保留名称，但必须加管理员权限，不留下未鉴权旁路。
- 现有 Hermes/MCP 接入需要配置管理凭证；没有凭证时明确报告需要登录/配置，不降级匿名管理员。
- 正式升级前核验新鲜进程身份、空闲任务和数据库备份，按约定切换工作台；不重启 Hermes Gateway 或 ComfyUI，不重复使用旧 PID。

## 9. 实施顺序与完成条件

### 第一阶段：闭合最小用户使用链路

这是同一个完整交付，不能把服务端隔离或 AI 配套挪到后续：

1. SQLite 兼容迁移、首次管理员、登录/退出、账户启停与统一身份校验。
2. 用户管理、直接场景授权、revision 冲突保护。
3. 管理端与用户端入口、授权已发布场景目录、业务输入表单。
4. 本人服务端草稿、固定版本提交、本人运行和媒体结果；封闭旧 API 的旁路。
5. 状态允许的用户任务操作；暂不开放的操作必须明确隐藏并在服务端拒绝，不能无保护复用管理接口。
6. HTTP/MCP/机器契约/功能矩阵/指南/生成文档/隔离回归同时交付。

素材库只有归属、共享和媒体权限全部闭合后开放给用户。第一版不需要高级角色、组织、配额、计费或每用户模型配置。

### 必测验收

- 未登录、普通用户访问管理 UI/API/MCP 的拒绝路径。
- 两用户不同授权；空授权；新场景不自动授权；已授权但未发布；草稿名称与发布名称不同。
- 禁用用户、撤销授权、缓存页面与旧会话不能继续提交；发布变更显式冲突，已接受运行不切版。
- 两用户的草稿、任务、事件、输出、素材和媒体不能串读；直接猜 ID、原始媒体 URL、HEAD/Range 与旧路由均不能绕过。
- 任务归属不可从请求 body 伪造；用户不得提交任意工作流或更改项目目录。
- 用户/授权/草稿更新的旧 revision、并发、分页边界和游标失效。
- 创建账户、保存草稿、提交运行等响应丢失时使用原 ID 对账。
- 管理员和用户各至少一条真实 stdio MCP 隔离闭环；使用临时项目/端口/数据与不调用真实模型的确定性步骤。
- 历史数据保留并仅管理可见；退出或切换账户不会恢复其他身份的 outbox。
- `npm run check` 和生成文档漂移检查通过后才宣称业务功能完成；额外凭证/运维步骤明确交付。

## 10. 启用步骤与第一版限制

1. 按正常正式升级流程核验进程身份、确认空闲、备份并切换同一 APP_DATA_DIR。不要在旧后台运行时覆盖其正在提供的 dist 前端。
2. 服务器本机访问根入口，显式创建首个管理员（用户名/显示名/至少10位密码）。不生成默认账号，不把旧匿名会话升级为管理员。setup只允许loopback；远程设备先等本机初始化完成。
3. 管理员进入 /admin → 用户管理，创建账户并保存场景授权。未发布的授权场景在用户端不可见。普通用户登录后进入 /app。
4. 浏览器使用24小时会话；本人账户中的 API token 有效90天、密钥仅在创建回执显示一次。Hermes comfyui-dev 使用管理员本人 token；普通用户 AI 使用用户自己的 token，设置 ZANE_API_TOKEN。权限从服务端读取，不由 profile 名决定。
5. 停用/角色调整/重置密码使既有会话和 API token 失效；修改授权实时生效但不注销用户。只撤销授权不会自动取消已接受任务，用户仍可读原结果、取消本人在途任务。
6. 升级前全局浏览器 outbox 不自动迁入某个账号。管理端提示可下载原始备份；原内容不删除，不自动重放。新管理 outbox 与提交意图按 userId 隔离。

没有高级角色、组织/租户、配额/计费、账户自助注册/找回密码、共享素材库、历史认领、管理员代编辑用户草稿。stdio 工具目录仍是完整静态目录；get_workbench 按身份发现可用操作，越权调用由 HTTP 返回403，不能依靠客户端隐藏工具作权限校验。用户 get_workbench 不返回全局任务数量/项目路径/连接信息。大结果保留分页与明确省略标记，UI支持逐项结果，较大的单值使用MCP按字段/分段读取。

预备部署可使用 DIST_DIR 指向临时构建目录完成 npm run check；正式升级后的首次账户配置和 Hermes 凭证配置是明确的启用步骤，不是已自动完成的上线。
