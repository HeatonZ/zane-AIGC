# 素材、人工确认与镜头选版

这三项使用现有 SQLite 元数据、运行快照和本地媒体归档，不引入新外部服务，也不增加模型调用。

## 1. 真实素材库

- 左侧“素材库”展示实际素材，不再展示静态示例图。可以导入图片、视频、音频。
- 运行最终输出、步骤输出、已完成逐项输出旁的“存入素材库”可收藏单个文件。
- 分类：角色、场景、道具、音色、普通素材；支持名称、分组、标签及检索。
- “详情 / 版本”可修改信息、上传新版本、查看历史版本和来源生成参数。
- 创作页所有媒体输入提供“从素材库选择”，可以与上传文件和本地路径混用。
- 上传对话框在列表输入上可一次多选：每个文件独立上传为一条素材版本，按选择顺序追加到输入；上传失败或回执未确认的文件各自保留素材ID，可逐个对账，不影响已添加的文件。
- 引用必须指定 assetId + assetVersion，版本不会随素材更新漂移。
- 媒体独立保存至项目目录的 .zane/assets/blobs，以 SHA-256 + 扩展名去重。素材不依赖原运行目录；元信息和全部版本保存在 SQLite 中。
- 归档只隐藏列表项，不物理删除文件。已归档素材的旧版本仍可被历史任务读取；暂不自动回收 blob，因此不要手工删除正在使用的资产文件。
- 保存来源参数包含运行 ID、步骤/逐项、输入和步骤快照；不复制连接凭证。

API：GET/POST /api/v1/assets、POST /api/v1/assets/upload、GET/PATCH /api/v1/assets/:id、GET /api/v1/assets/:id/versions/:version/media。媒体路由支持 HEAD、Range。上传端点接受 application/octet-stream，单文件限制 250 MB；媒体收藏下载与磁盘复制按流处理，原始上传当前仍由 Express raw body 缓冲。

## 2. 人工确认关卡

在流程设计器的步骤设置勾选“完成后等待人工确认”，可添加确认说明。每个节点均可设置；逐项节点在整批完成后确认，不是逐项暂停。

状态：queued → running → waiting → queued → running。等待状态提交到 SQLite 和运行归档后，释放 worker 名额，不占着外部请求或浏览器连接。

在运行记录的确认面板中：

- “确认并继续”：直接接受结果，或先编辑单次节点的文本/JSON/媒体结果再接受。媒体可从素材库替换，选定版本在执行前解析。
- “退回重做本步骤”：可修改提示词；前序完成节点不重跑，当前节点重做后再次等待确认。
- “取消运行”：结束本次执行。之后断点续跑仍需确认未通过的关卡，不能借取消/续跑绕过确认。
- 保留确认历史、原结果和编辑结果。等待时直接使用普通续跑或局部重做接口会返回 REVIEW_REQUIRED；可以取消后再用局部重做。
- 每次等待都有新的 reviewId；旧页面、重复提交和并发确认返回 409，不重复执行下游。
- 关页面、正常重启后等待状态不变；已确认但尚未执行的队列快照也能恢复。

API：POST /api/v1/runs/:runId/review，body 为 { reviewId, action: approve | redo, outputs?, stepChanges? }。outputs 只支持单次节点；redo 可更改 promptTemplate、hermesProfile、capabilityConfig、inputs。界面目前提供提示词编辑，其余参数可用 API 修改。

## 3. 镜头选版与成片整理

终态运行中，逐项视频步骤提供“镜头选版 / 合成”。新建清单后，会固定当次运行的成功镜头；失败或未生成的镜头保留空位，不静默漏镜。保存的清单也可从素材库的“选片清单”重新打开。

- 候选范围只包含同一修订/续跑链的终态运行。
- 镜头归组按分镜源值匹配，不只按数组序号；内容不同的同序号镜头不会被误套。重复相同内容时保守按原索引匹配。
- 清单内有固定 shotId；每镜可选择不同运行版本。选定片段复制进独立资产归档，清单固定引用素材版本。
- 新候选不会覆盖既有选择；可手动刷新候选、调整镜头顺序。
- 完整选片后才允许整理。整理提交一个只包含 core.code 自定义代码步骤的新运行，不调用 Writer、Hermes 或 ComfyUI 生成。
- 整理输入保存清单完整快照与版本；自定义代码步骤按镜头顺序输出成片媒体序列，manifest 记录每镜固定的素材版本，不生成新媒体文件。
- 第一版不提供裁切、轨道编辑、转场或字幕时间线；不是完整剪辑器。
- 若原运行文件被手工移除，已经选定并归档的片段仍能合成；未选定候选可能无法预览/保存。

API：GET/POST /api/v1/clip-selections、GET/PATCH /api/v1/clip-selections/:id、GET /api/v1/clip-selections/:id/candidates、POST /api/v1/clip-selections/:id/compose。修改与合成都要求当前 revision，过期页面返回 409。

## 数据迁移与启用

SQLite 从 user_version 1 添加 production_documents 表升级至版本 2；原工作区、运行、步骤、事件表保持不变。数据库高于版本 2 时拒绝打开，避免旧程序误写新格式。

需要重启更新后的后台才能启用新 API；只刷新前端不够。本轮不自动重启正式服务，也不调用真实付费生成服务。
