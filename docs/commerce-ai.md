# 电商套图：AI直接生成完整图片

## 目标与边界

用户提供商品图片和需求，由 AI 设计并直接生成整套电商成图。构图、背景、图形、文字层级以及需要出现在画面中的文案都由图像模型在同一次生成中完成。

**不是商品照片加程序标题，不生成等待排版的无字底图。** 新模板不包含 `add_text` 输入、`layout` 字段、文字对齐、条件排版或二次图片合成。最终图片就是 ComfyUI 返回并归档的原始图片；文字正确性和设计质量需要查看真实成图，不以流程跑通替代设计验收。

## 复用基础步骤

用户看到的流程是：**商品与需求 → AI设计整套 → 确认方案 → AI直接生成样张 → 确认后生成剩余图片 → 查看与下载。**

模板共10个步骤：商品事实 Writer、整套设计 Writer、计划校验、自定义代码合并商品/风格参考、方案确认、AIXG 完整成图提示词、生成任务关联、基础 ComfyUI 样张、基础 ComfyUI 剩余逐张生成、自定义代码按样张→剩余顺序交付成图并审核。两个自定义代码步骤都用 `core.code` 的媒体输出端口：按 `filename` 选择本次输入/本次运行里已有的图片，不产生、不改名、不拼接媒体。模板不使用 `media.select_references`、`media.image_layout`、`text.template`、`core.manual` 等已退役执行方式。

`data.zip` 只检查计划数量、唯一ID和数据结构，并关联同一张的计划与生图提示词；不对齐文字、不排版、不修改图片。参考图集合对所有设计相同，因此不再有逐张“媒体包”：`references` 步骤（`core.code`）把 `input.product_images` 与 `input.style_images` 按商品→风格顺序合并成一个 `image_list` 输出，同时输出 `reference_map`（`<Product N>`/`<Style N>` → 真实附件序号 `<Picture N>`）；AIXG、样张和剩余生成都直接绑定这组有序附件。交付步骤（`core.code`）再按样张→剩余顺序返回本次运行的原始成图。没有电商专用执行器。

## AI设计要求

Writer 输出整套视觉方向和恰好1–8张（默认5张）的设计计划。每项为 `{id,role,goal,brief}`，不要求模型选择或编号素材，也不输出后置排版数据。每张设计收到的参考图固定是本次输入的全部商品图与全部风格图（可选空组保持为空），由 `core.code` 在运行期合并，避免 Writer 漏选、错选或引用越界导致流程在生图前失败；`brief` 需要引用素材时写 `<Product N>`/`<Style N>`，由 `reference_map` 映射到真实附件序号。

`brief` 是一张完整电商设计稿的要求，包含主体构图、背景、图形、视觉焦点和所需短文案；需要文字时将准确短文案直接写入设计要求，图像模型负责生成。用户明确要求无字时才不加文字，但仍需完整视觉设计。AIXG 不得擅自删去文字、版式、图形或情境，也不能把设计收缩为只换背景、只移动商品或保持居中。

商品事实与视觉创作分开约束：不能编造品牌、参数、功效、材质、认证或配件；但可以设计色块、字体层级、放大细节、标注、背景和合理人物情境。商品参考是外观依据，风格参考仅提供视觉方向。未知信息和风险提醒留在内部策划，不作为消费者画面文案。每张需有不同的沟通任务和构图，不能用重复外观图凑套图。

## 配置、发布与历史

模板 `examples/scenes/commerce-ai.json` 可通过现有 HTTP/MCP 场景服务创建草稿或显式更新既有场景。替换原“电商套图”入口须保留目标 sceneId，读取当前 revision 后保存、校验、显式发布。旧发布快照、旧后置排版流程和历史运行不自动替换；旧输入契约继续取其固定发布版本，旧任务续跑仍采用原快照。

需要启用 `writer`、`aixg` Profile 并核对已有 `Zane/i2i_UI.json` 节点：471.images/prompt、476.seed、481.aspect_ratio/megapixels、479.switch、461.images。没有切换工作流、改写 Hermes 上游或创建新的任务数据库。工作台代码升级仍按隔离验收、空闲检查、数据备份与正常切换执行；不重启 Hermes Gateway 或 ComfyUI。

## 审核与验收

方案审核检查完整设计，样张审核检查它是否真的是电商成图而非普通商品照片，成图审核检查商品、文字、视觉统一性和逐张差异。样张不合格应先退回，不能继续批量生成。AI文字不能承诺准确，生成商品也不能承诺像素级保真，必须看图核对。

`npm run test:commerce-ai:smoke` 用临时项目、SQLite、端口与本机模拟模型，经真实 stdio MCP 覆盖草稿revision、发布对账、输入契约、完整设计提示词与真实附件传递、单张与多张、审核、无排版的原始模型图片交付、异常参数、分页、重跑、失败恢复及ZIP下载。测试不调用真实模型，也不证明审美质量。交付前须通过 `npm run check` 与 `npm run docs:ai:check`。
